# 12 · 数据字典与命名规范

> 版本：v0.2.1 ｜ 依赖：全部模块 ｜ 总纲：`../核心玩法策划.md`

## 1. 模块目标

给策划与程序提供统一的**命名、枚举、字段与效果配置规范**，避免同一概念在不同模块/代码中出现多个名字或不同结构。

> 本模块只定义“逻辑字段与命名”；具体配置文件格式（JSON/CSV/ScriptableObject 等）由工程实现决定，不在此发明新架构。

## 4. 效果配置规范

### 触发时机（`trigger`）

| 枚举 | 时机 |
|------|------|
| `ON_BATTLE_START` | 战斗开始 |
| `ON_TURN_START` | 玩家回合开始 |
| `ON_PLAY` | 出卦/使用卡牌时 |
| `ON_HIT` | 命中敌人时 |
| `ON_KILL` | 击杀敌人时 |
| `ON_DAMAGE_TAKEN` | 玩家受伤时 |
| `ON_TURN_END` | 回合结束 |
| `ON_BATTLE_END` | 战斗结束 |

### 作用对象（`target`）

| 枚举 | 对象 |
|------|------|
| `SELF` | 玩家 |
| `ENEMY` | 当前敌人 |
| `ALL_ENEMIES` | 所有敌人 |
| `RANDOM_ENEMY` | 随机敌人 |
| `HAND` | 手牌 |
| `DECK` | 牌堆 |
| `ALL` | 全体 |

### 数值类型（`value_type`）

| 枚举 | 说明 |
|------|------|
| `FLAT` | 固定值加减 |
| `PERCENT` | 百分比加减 |
| `MULT` | 乘法倍率 |
| `SET` | 直接设为某值 |

### 持续时间（`duration`）

| 枚举 | 说明 |
|------|------|
| `INSTANT` | 立即结算 |
| `TURN` | 持续 N 回合 |
| `BATTLE` | 本场战斗 |
| `RUN` | 本局游戏 |
| `PERMANENT` | 永久（局外） |

### 条件（`condition`）

- 支持组合条件：`element == FIRE`、`hexagram_id == H11`、`hand_size >= 2`、`hp_percent < 0.5` 等。
- 条件字段必须可序列化；复杂脚本逻辑必须显式标注 `[未接线]` + TODO。

```

```

## 6. 配置与兼容规则

1. 所有 ID 一经发布**不可重命名**；需要改名时新增 ID 并保留旧 ID 映射。
2. 数值字段必须带默认值；缺失时使用默认值并输出警告。
3. 效果配置必须声明 `trigger` / `target` / `value_type` / `duration`，不允许“隐式默认”。
4. 新增枚举必须同步更新本数据字典与相关模块文档。
5. 局外/局内存档字段只增不删；删除字段必须提供迁移逻辑；战斗快照字段与恢复边界以 13 为准。

## 8. 待验证问题

1. 64 卦 ID 用 `H01–H64` 还是 `UPPER_LOWER`（如 `QIAN_KUN`）？前者简短，后者可读。
2. 效果配置用“数据驱动 + 少量脚本”还是“全脚本”？需评估内容迭代速度与性能。
3. 状态/附魔的叠加规则是否需要单独的“叠加策略”字段？
4. 是否需要为“天劫词条”单独建表，还是复用效果配置？
5. 存档结构是否需要一个独立的 `schema_version`（与全局 `save_version` 分离），以支持分模块迁移？
