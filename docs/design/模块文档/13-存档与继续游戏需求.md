# 13 · 存档与继续游戏需求

> 版本：v0.2.2 ｜ 依赖：01 总流程、02 单局、03 战斗、09 境界、12 数据字典 ｜ 总纲：`../核心玩法策划.md`

## 1. 目标与核心需求

### 1.1 目标

玩家退出游戏后可以保存当前进度，下次进入主界面时通过「继续游戏」回到上次的进度，不需要从头开始。

### 1.2 核心需求（必须满足）

1. **局外进度永久保存**：道行、解锁、图鉴、天劫等级等不因退出而丢失。
2. **局内进度可继续**：如果玩家在对局内，继续游戏后回到该对局的当前节点（路线页 / 坊市 / 奇遇 / 战斗）。
3. **战斗内恢复到“玩家尚未行动的状态”**：如果玩家在战斗中退出，继续游戏后回到**当前回合的玩家行动阶段开始**——即回合开始效果已结算、玩家尚未执行出卦/弃牌/使用符箓等任何操作的状态。
4. **不恢复操作中间态**：不保存“动画播放到一半”“伤害结算到一半”“敌人回合行动到一半”的状态。
5. **不重掷随机数**：继续游戏后手牌、抽牌堆顺序、敌人意图、商店商品等与存档时一致。

> 核心原则：**存档点是“可安全恢复的边界”，不是“任意时刻的快照”。**

---

## 2. 术语定义

| 术语 | 定义 |
|------|------|
| 局外存档（Meta Save） | 永久数据：道行、解锁、图鉴、天劫、统计 |
| 局内存档（Run Save） | 当前一局的数据：境界、关卡、牌组、资源、构筑等 |
| 战斗快照（Battle Snapshot） | 一场战斗在“玩家回合开始、尚未行动”时的完整状态 |
| 玩家尚未行动状态 | 玩家回合开始效果（回灵、抽牌、回合开始法宝）已结算，玩家尚未执行任何出卦/弃牌/符箓操作的瞬间 |
| 继续游戏（Continue） | 主界面读取存档并恢复到对应页面的入口 |
| 自动存档 | 在安全节点自动写入，不需要玩家手动操作 |
| 手动存档 | 玩家主动保存；v1 不要求，作为后续扩展 |

---

## 3. 存档分层

| 层级 | 保存内容 | 生命周期 | 备注 |
|------|----------|----------|------|
| 局外存档 | 道行、解锁、图鉴、天劫、统计 | 永久 | 一局结束/退出时更新 |
| 局内存档 | 当前境界、关卡、牌组、资源、构筑、节点状态 | 本局结束前 | 一局结束清空 |
| 战斗快照 | 玩家回合开始时的战斗状态 | 本场战斗结束前 | 覆盖写入，只保留最新一份 |
| 设置存档 | 音量、语言、按键、画面 | 永久 | 与局内/局外存档分离 |

> v1 只要求 **1 个自动存档槽**（局内存档 + 战斗快照共用）；手动多槽位作为后续扩展。

## 4. 存档内容

### 4.1 局外存档字段

| 字段 | 说明 |
|------|------|
| `save_version` | 存档结构版本，用于迁移 |
| `daoxing` | 道行 |
| `unlocks` | 已解锁武器/法宝/符箓/道途/图鉴条目 |
| `codex` | 每个卦象的发现状态、使用次数、熟练度 |
| `tribulation_level` | 已解锁的最高天劫等级 |
| `stats` | 局数、通关数、最高境界、最长连胜等 |
| `updated_at` | 最后更新时间 |

### 4.2 局内存档字段

| 字段 | 说明 |
|------|------|
| `run_id` / `seed` | 本局唯一 ID 与随机种子 |
| `realm_id` | 当前境界：炼气 / 筑基 / 金丹（长线含元婴及以上） |
| `stage_index` | 当前关卡序号 1–9 |
| `cleared_stages` | 已通关关卡列表 |
| `node_type` | 当前节点：`RUN_MAP` / `SHOP` / `EVENT` / `BATTLE` / `BATTLE_RESULT` / `REALM_PROMOTION` |
| `player_hp` / `player_max_hp` | 玩家气血（跨战斗保留） |
| `shield` | 当前护盾（跨战斗不保留，按规则重置） |
| `spirit_stones` | 灵石 |
| `deck` | 牌组：每张牌的实例 ID、卦 ID、品级、词缀、是否锁定 |
| `draw_pile` / `hand` / `discard_pile` | 仅在战斗快照中保存，且保留顺序 |
| `treasures` | 法宝列表（槽位顺序） |
| `talismans` | 符箓列表 |
| `weapon` | 武器/功法：ID、基础力道、等级、词缀 |
| `enchant_slots` | 附魔槽（仅战斗快照） |
| `shop_state` | 坊市商品、价格、刷新次数（当前节点为 `SHOP` 时） |
| `event_state` | 奇遇选项/结果（当前节点为 `EVENT` 时） |
| `updated_at` | 最后更新时间 |

### 4.3 战斗快照字段（核心）

| 字段 | 说明 |
|------|------|
| `battle_id` | 当前战斗 ID |
| `enemy` | 敌人 ID、HP、护盾、五行、状态、当前意图 |
| `turn_number` | 当前回合数 |
| `player_hp` / `shield` / `spirit` | 玩家气血、护盾、灵力 |
| `hand` | 手牌（实例 ID + 顺序） |
| `draw_pile` | 抽牌堆（有序） |
| `discard_pile` | 弃牌堆（有序） |
| `enchant_slots` | 当前附魔槽内容与剩余持续 |
| `player_statuses` | 玩家身上的状态 |
| `turn_start_effects_resolved` | 回合开始效果是否已结算（固定为 `true`） |
| `treasure_counters` | 本场战斗内的法宝计数器 |
| `rng_state` | 随机数状态，保证继续后不重掷 |

> 战斗快照在**每个玩家回合开始时**写入；写入时机是“回合开始效果结算完成、玩家尚未操作”的瞬间。

## 5. 存档时机

### 5.1 自动存档点（v1）

| 时机 | 写入内容 |
|------|----------|
| 开局确认后 | 局内存档（当前节点 `RUN_MAP`） |
| 每场战斗初始化后 | 战斗快照（初始手牌、敌人意图） |
| 每个玩家回合开始 | 覆盖战斗快照（玩家尚未行动） |
| 战斗胜利结算后 | 局内存档（更新关卡/奖励） |
| 坊市购买/刷新后 | 局内存档（保存商品与刷新次数） |
| 奇遇选项结算后 | 局内存档（保存结果） |
| 境界晋升后 | 局内存档（更新境界/关卡） |
| 一局结束 | 局外存档（道行/解锁/图鉴） |
| 退出到主界面时 | 若对局未结束，写一次局内存档 |

### 5.2 禁止/延迟存档的时机

- 动画播放中；
- 伤害/状态结算中；
- 敌方回合行动中；
- 玩家已操作但尚未结束回合时（**不保存操作中间态**）；
- 存档写入失败时，保留上一份有效存档并提示。

> 如果玩家在“已操作但未结束回合”时关闭游戏，继续游戏会回到**本回合的玩家回合开始快照**，该回合已执行的操作不保留。这是为了满足“玩家尚未行动的状态”这一硬性需求。

## 6. 继续游戏流程

```
主界面启动
   │
   ├─ 没有有效存档 → 只显示「开始修行」
   └─ 有有效存档 → 显示「继续游戏」+「开始新游戏」
                        │
                        ▼
                  读取局外存档 + 局内存档 + 战斗快照
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
   节点=RUN_MAP     节点=SHOP/EVENT   节点=BATTLE
   进入路线页        进入对应页面      恢复战斗快照
                                      （玩家尚未行动）
```

### 恢复目标

| 存档节点 | 继续游戏后进入 |
|----------|----------------|
| `RUN_MAP` | 修行路线页，当前关高亮 |
| `SHOP` | 坊市页，商品与刷新次数与存档一致 |
| `EVENT` | 奇遇页，恢复到事件开始或已结算结果 |
| `BATTLE` | 战斗页，恢复到玩家回合开始快照 |
| `BATTLE_RESULT` | 战斗结算页（胜利奖励已锁定） |
| `REALM_PROMOTION` | 境界晋升页 |
| `RUN_RESULT` | 一局结算页 |

### 不重掷原则

- 手牌、抽牌堆顺序、弃牌堆顺序与存档一致；
- 敌人当前意图与存档一致；
- 坊市商品、价格、刷新次数与存档一致；
- 奇遇已出现的结果与存档一致。

---

## 7. 战斗内快照规则（核心需求）

### 7.1 快照定义

“玩家尚未行动的状态”指：

1. 当前是玩家回合；
2. 回合开始效果已结算：灵力回复、抽牌至上限、回合开始法宝触发；
3. 玩家尚未执行任何操作：没有出卦、没有弃牌、没有使用符箓；
4. 敌人意图已生成并显示。

### 7.2 继续后的表现

- 玩家看到与退出时**相同的手牌、灵力、气血、护盾、附魔、敌人状态与意图**；
- 玩家可以直接继续决策，不需要重新抽牌/重新生成意图；
- 回合开始效果不会重复触发。

### 7.3 边界

| 玩家退出时所在阶段 | 继续游戏后 |
|--------------------|------------|
| 玩家回合开始、尚未操作 | 回到该快照，状态完全一致 |
| 玩家已出卦/弃牌/用符箓，未结束回合 | 回到本回合开始快照；已执行操作不保留 |
| 敌方回合行动中 | 回到本回合开始快照；敌方行动不保留 |
| 战斗胜利/失败结算中 | 若胜利已锁定则回到结算页；否则回到最近快照 |
| 动画播放中 | 忽略中间态，回到最近安全快照 |

> `[待验证]` 上述规则可能被玩家用于“操作后关闭重开”来撤销本回合操作。是否需要限制（例如本回合重开后不记录成就/不改变掉落）需在 playtest 中评估。

## 8. 存档槽与覆盖规则

| 规则 | v1 方案 |
|------|---------|
| 自动存档槽 | 1 个（局内存档 + 战斗快照） |
| 手动存档槽 | 暂不提供 `[未接线]` |
| 开始新游戏 | 若已有局内存档，二次确认“放弃当前进度并开始新一局？” |
| 删除存档 | 主界面/设置提供“删除存档”，二次确认 |
| 备份 | 保留上一份有效存档作为备份，主存档损坏时尝试恢复 |
| 覆盖时机 | 只在安全存档点覆盖；写入使用“临时文件 + 原子替换” |

## 9. 数据一致性、版本与迁移

| 项目 | 要求 |
|------|------|
| `save_version` | 每次存档写入；读取时校验 |
| 版本迁移 | 旧版本存档必须提供迁移逻辑；无法迁移时提示并保留局外数据 |
| 未知 ID | 读取时忽略未知物品并输出警告；不直接崩溃 |
| 牌组一致性 | 读档后校验“手牌 + 抽牌堆 + 弃牌堆 + 已移除牌 = 牌组总数” |
| 数值裁剪 | HP/灵力/护盾等读取后按上限裁剪 |
| 原子写入 | 先写临时文件，成功后替换主存档；失败保留旧存档 |
| 存档频率 | 只在安全点写入，不每帧写入 |
| 加密/防篡改 | v1 不要求；后续如需可加校验和 |

## 10. 异常与边界

| 情况 | 处理 |
|------|------|
| 存档损坏 | 尝试读取备份；失败则提示“存档损坏”，允许开始新游戏；局外数据尽量保留 |
| 版本不兼容 | 尝试迁移；失败则保留局外数据，局内进度清空并提示 |
| 磁盘写入失败 | 保留上一份有效存档；提示“保存失败，请检查磁盘空间” |
| 战斗中断电/崩溃 | 继续游戏恢复到最近一次玩家回合开始快照 |
| 退出时正在动画 | 延迟到下一个安全点写入；若强制退出，使用上一份快照 |
| 资源缺失（内容更新删除物品） | 忽略缺失物品并折算为灵石；输出警告 |
| 多存档冲突 | v1 只有 1 个自动槽，不存在冲突；后续多槽位再定义 |

## 11. 验收标准

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| S1 | 主界面继续游戏 | 有有效存档时显示“继续游戏”，无存档时不显示 |
| S2 | 战斗内继续 | 从战斗内退出后继续，回到玩家回合开始；手牌/牌堆/敌人状态/意图/资源与存档一致 |
| S3 | 不重复触发 | 继续后回合开始效果不重复触发 |
| S4 | 牌组一致 | 手牌 + 抽牌堆 + 弃牌堆 + 已移除牌 = 牌组总数，无重复/丢失 |
| S5 | 商店一致 | 从坊市退出后继续，商品/价格/刷新次数与存档一致，不重掷 |
| S6 | 奇遇一致 | 从奇遇退出后继续，事件与已选结果一致 |
| S7 | 局外永久 | 道行/解锁/图鉴/天劫在退出、重开游戏后仍保留 |
| S8 | 损坏保护 | 存档损坏时不崩溃，能提示并保留局外数据 |
| S9 | 性能 | 单次存档/读档在 2 秒内完成（目标值，非硬性） |
| S10 | 连续读写 | 连续 100 次存档/读档无数据损坏 |

## 13. 待验证问题

1. v1 只做 1 个自动存档槽是否够？是否需要 3 个手动槽？
2. 战斗中关闭后回到回合开始，是否会被玩家用于“撤销操作”？是否需要限制？
3. 是否需要在玩家每次操作后也保存（会回到操作中间，违背本需求）？
4. 商店刷新后立即存档是否会被用于“看商品后重开”？是否需要保存随机种子防止重掷？
5. 存档加密/校验和是否在 v1 需要？
6. 云存档/多设备同步是否在后续范围？
7. 存档写入失败时，是否应该强制返回主界面，避免玩家继续游戏却没有有效存档？
