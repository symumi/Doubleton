# 02｜战斗系统实现

> 版本：v0.1｜依赖：[01-架构与目录.md](01-架构与目录.md)

## 1. 范围

本文定义单场战斗的程序实现。坊市、奇遇、局外成长不在本文范围内。

战斗必须支持：

- 玩家回合与敌人回合
- 摸牌、弃牌、出卦、结束回合
- 内卦和外卦的顺序选择
- 64 卦查询与效果生成
- 伤害预览与实际结算
- 状态和附魔
- 敌人意图
- 胜负判定

## 2. 战斗状态机

```text
BattleStart
    ↓
PlayerTurnStart
    ↓
PlayerAction
    ├─ PlayHexagram → Resolving → PlayerAction
    ├─ Discard      → PlayerAction
    ├─ UseTalisman  → Resolving → PlayerAction
    └─ EndTurn      → EnemyTurn
EnemyTurn
    ↓
PlayerTurnStart
BattleEnd
```

### 2.1 状态职责

| 状态 | 行为 |
|---|---|
| `BattleStart` | 初始化牌堆、敌人、武器、意图和随机种子 |
| `PlayerTurnStart` | 灵力恢复、摸牌、状态结算、附魔计时 |
| `PlayerAction` | 等待玩家指令，可反复预览但不可修改状态 |
| `Resolving` | 执行一个指令的计算和应用，期间锁输入 |
| `EnemyTurn` | 执行敌人意图、状态结算、选择下一意图 |
| `BattleEnd` | 停止输入，输出结算数据 |

`Resolving` 是逻辑阶段，不是动画阶段。逻辑可以先完成，UI 再播放事件。

## 3. 玩家指令

MVP 只保留必要指令：

```csharp
PlayHexagramCommand(innerCardUid, outerCardUid)
DiscardCardsCommand(cardUids)
UseTalismanCommand(talismanId, targetUid)
EndTurnCommand()
```

指令校验：

- 当前是否处于 `PlayerAction`
- 灵力是否足够
- 卡牌是否仍在手牌
- 内外卦是否选择了不同卡牌
- 弃牌次数是否允许
- 符箓是否存在且可用

校验失败只返回错误结果，不修改战斗状态。

## 4. 出卦流程

```text
选择内卦
  ↓
选择外卦
  ↓
实时计算 HexagramDefinition
  ↓
预览伤害、状态、资源变化
  ↓
点击出卦
  ↓
再次校验
  ↓
生成 BattleCalculation
  ↓
应用状态并生成 BattleEvent
```

规则：

- 内卦决定行为主体和攻击五行。
- 外卦决定修饰参数。
- 特殊卦只覆盖明确配置的字段。
- 两张牌必须来自当前手牌。
- 结算完成后两张牌进入弃牌堆。
- 附魔在攻击结算后写入。

## 5. 伤害计算

### 5.1 公式

MVP 使用以下固定顺序：

```text
基础 = 武器基础力道 + 内卦牌卦力 + 外卦牌卦力

总伤害 =
    基础
    × 卦象倍率
    × 五行系数
    × (1 + 法宝加法乘区)
    × 法宝乘法乘区
    × 会心系数
    × 防御修正
```

计算使用整数或万分比定点数。UI 最终显示整数。

### 5.2 固定计算阶段

| 阶段 | 内容 |
|---|---|
| 1. 基础值 | 武器力道、两张牌卦力、词缀基础修正 |
| 2. 卦象 | 内卦行为、外卦修饰、特殊卦覆盖 |
| 3. 五行 | 下卦五行 vs 敌人五行 |
| 4. 法宝 | 先加算，再乘算 |
| 5. 会心 | MVP 使用确定性条件，不使用随机伤害 |
| 6. 防御 | 护盾、破甲、抗性 |
| 7. 状态 | 易伤、虚弱等修正 |
| 8. 收尾 | 最小伤害、上限和显示取整 |

任何阶段都不能在 UI 中重复实现。

### 5.3 五行系数

```text
克制：×1.5
被克：×0.67
普通同属性：×1.0
敌人同属性：×0.85
```

对敌结算以 `×0.85` 为统一规则，避免与原型图冲突。该数值仍需 playtest。

### 5.4 伤害结果

计算返回完整明细：

```text
DamageBreakdown
- baseDamage
- hexagramMultiplier
- elementMultiplier
- artifactAdditive
- artifactMultiplicative
- criticalMultiplier
- defenseReduction
- finalDamage
```

`DamageBreakdown` 同时用于：

- 战斗界面预估
- 伤害数字
- 悬停详情
- 自动化测试断言

## 6. 预览与执行

### 6.1 预览

预览阶段必须满足：

- 不修改 `BattleState`
- 不消耗手牌和灵力
- 不推进随机数
- 不触发一次性的战斗状态

预览输入：

```text
BattleState
+ innerCard
+ outerCard
+ weapon
+ artifacts
+ enemy
```

输出 `BattleCalculation`，UI 只负责展示。

### 6.2 执行

执行阶段：

1. 重新计算一次，防止状态变化导致预览过期。
2. 检查计算结果是否仍合法。
3. 将 `BattleCalculation` 应用到状态。
4. 生成事件队列。
5. 锁住输入，等待 UI 播放完毕。
6. 恢复 `PlayerAction`。

### 6.3 随机规则

MVP 不允许随机伤害。

随机只用于：

- 摸牌
- 弃牌或牌堆顺序
- 敌人意图选择（若配置为随机）
- 后续事件和商店

所有随机必须使用战斗种子，不允许直接调用 `UnityEngine.Random`。

## 7. 卦象与效果

### 7.1 卦象组成

```text
Hexagram = InnerTrigram × OuterTrigram
```

- `InnerTrigram`：攻击行为、目标模式、攻击五行
- `OuterTrigram`：倍率、连击、会心、资源、扩散等修饰
- `SpecialHexagram`：对指定字段进行覆盖

### 7.2 效果操作

效果使用可组合操作，不直接写 64 个类：

| 操作 | 用途 |
|---|---|
| `Damage` | 单体或群体伤害 |
| `ApplyStatus` | 施加状态和层数 |
| `GainShield` | 获得护盾 |
| `DrawCard` | 抽牌 |
| `GainEnergy` | 恢复灵力 |
| `DiscardCard` | 弃牌 |
| `ModifyDamage` | 修改伤害乘区 |
| `ExtraTrigger` | 追加触发 |
| `ChangeIntent` | 修改敌人意图 |

特殊卦优先通过组合操作实现；只有无法数据化时才增加专用 Handler。

## 8. 状态与附魔

### 8.1 状态

`StatusInstance` 至少包含：

```text
statusId
stacks
duration
sourceUid
remainingTriggers
```

状态触发点：

- 回合开始
- 出卦前
- 伤害计算前
- 受到伤害后
- 造成伤害后
- 回合结束

MVP 状态只保留：

- 灼烧
- 易伤
- 虚弱
- 护盾
- 破甲
- 寒滞

### 8.2 附魔

`EnchantInstance` 至少包含：

```text
effectId
sourceHexagramId
remainingTurns
orderIndex
```

规则：

- 最多 3 个。
- 槽满后先入先出。
- 在攻击结算后写入。
- 持续时间以玩家回合边界结算。
- 附魔只写入“持续部分”，本手即时伤害不在附魔槽重复触发。

## 9. 敌人回合

敌人回合执行顺序：

```text
回合开始触发
  ↓
执行当前意图
  ↓
伤害/状态/召唤结算
  ↓
回合结束触发
  ↓
选择下一意图
  ↓
玩家回合开始
```

敌人意图必须在下回合开始前确定，并保存为运行时数据，供 UI 显示。

MVP 敌人 AI 使用配置化意图表：

```text
EnemyDefinition
- 意图列表
- 权重或顺序
- 血量阈值
- 禁用条件
```

不使用行为树。

## 10. Boss 规则改造

Boss 改造使用独立 Modifier，不写进普通敌人逻辑：

```text
IBattleModifier
- OnBattleStart
- OnTurnStart
- OnBeforeCalculate
- OnAfterResolve
```

MVP 只实现少量 modifier，并保证它们可以在预览中生效。任何会改变伤害的 modifier 都必须进入 `BattleCalculator`，不能只在表现层提示。

## 11. BattleEvent

`BattleEvent` 是逻辑层和表现层的唯一桥梁。

MVP 事件类型：

| 事件 | 表现 |
|---|---|
| `CardDrawn` | 卡牌飞入 |
| `CardDiscarded` | 卡牌飞出 |
| `HexagramFormed` | 卦象名称和组合展示 |
| `DamageDealt` | 伤害数字、受击抖动 |
| `ShieldChanged` | 护盾变化 |
| `StatusChanged` | 状态图标和层数 |
| `EnergyChanged` | 灵力变化 |
| `EnemyIntentChanged` | 意图刷新 |
| `BattleEnded` | 胜利或失败 |

事件必须包含足够的信息独立播放，不能要求 UI 再查询战斗状态推断前因后果。

## 12. 测试重点

至少覆盖：

- 8×8 共 64 个组合都能生成有效卦象。
- 内外卦顺序不同会生成不同卦象。
- 五行克制、被克、同属性系数正确。
- 法宝先加算后乘算。
- 预览计算不修改状态。
- 预览伤害与执行伤害一致。
- 状态层数、持续时间和触发顺序正确。
- 附魔槽满时按 FIFO 替换。
- 战斗胜利和失败都能正确结束。
- 随机种子相同的情况下战斗序列可复现。
