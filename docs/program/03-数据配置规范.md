# 03｜数据配置规范

> 版本：v0.1｜依赖：[01-架构与目录.md](01-架构与目录.md)、[02-战斗系统实现.md](02-战斗系统实现.md)

## 1. 目标

本文定义 MVP 阶段的静态配置和运行时数据结构，确保：

- 8 种八卦可以组合出完整 64 卦。
- 法宝、符箓、武器和敌人使用统一效果模型。
- 配置缺失可以被验证工具发现。
- 新增内容不需要修改核心战斗流程。

## 2. 配置与运行时分离

| 类型 | 用途 | 是否可修改运行时 |
|---|---|---|
| `CSV` | 静态定义、数值、文本、引用的编辑源 | 否 |
| `RuntimeState` | 单场战斗状态 | 是 |
| `Database` | 配置索引和查询 | 否 |
| `DTO` | 存档和迁移 | 是，独立于运行时对象 |

禁止在 CSV 配置中直接保存：

- 当前 HP
- 当前手牌
- 当前状态层数
- 当前附魔槽
- 当前敌人意图
- 随机数状态

### 2.1 当前 CSV 配置源

MVP 配置编辑源位于 `Assets/Resources/Config/Battle/`，运行时由 `ResourcesBattleConfigLoader` 读取，再交给 `CsvBattleConfigLoader` 解析为只读 `Definition`/`Database`。CSV 只保存静态定义，不保存当前 HP、手牌、状态层数、敌人意图或随机数状态。

效果列使用 `;` 分隔多个效果，单个效果格式为：

```text
EffectType|EffectTarget|ValueType|Value|StatusId|Stacks|Duration
```

示例：

```text
GainShield|Self|Flat|2|None|0|0
ApplyStatus|Enemy|Stacks|2|Burn|2|2
DrawCard|Self|Count|1|None|0|0
```
## 3. ID 规范

所有内容使用稳定字符串 ID，不使用数组下标作为长期标识。

```text
Trigram:   qian, dui, li, zhen, xun, kan, gen, kun
Hexagram:  qian_qian, kun_qian, qian_kun, ...
Weapon:    weapon_iron_sword
Artifact:  artifact_fire_lord_token
Talisman:  talisman_reverse
Enemy:     enemy_wood_demon
Status:    status_burn
Effect:    effect_damage_single
```

卦象 ID 固定格式：

```text
{outerTrigram}_{innerTrigram}
```

例如：

- `kun_qian` = 上坤下乾 = 地天泰
- `qian_kun` = 上乾下坤 = 天地否

必须始终明确“上卦在前、下卦在后”，避免内外顺序歧义。

## 4. 八卦配置

`TrigramDefinition` 建议字段：

```text
id
displayName
symbol
element
yinYang
innerBehaviorId
outerModifierId
baseQi
description
```

其中：

- `element`：金、木、水、火、土
- `yinYang`：阴、阳
- `innerBehaviorId`：作为内卦时使用
- `outerModifierId`：作为外卦时使用
- `baseQi`：仅作默认值，实际牌实例可覆盖品级卦力

MVP 八卦固定五行：

| 八卦 | 五行 | 阴阳 |
|---|---|---|
| 乾 | 金 | 阳 |
| 兑 | 金 | 阴 |
| 离 | 火 | 阳 |
| 震 | 木 | 阳 |
| 巽 | 木 | 阴 |
| 坎 | 水 | 阳 |
| 艮 | 土 | 阳 |
| 坤 | 土 | 阴 |

## 5. 八卦牌实例

`CardInstance` 是运行时对象：

```text
uid
trigramId
rank
qi
affixIds
sourceDeckId
```

规则：

- `uid` 只用于本次战斗或本局内的唯一标识。
- `rank` 决定基础卦力。
- `qi` 可以在符箓、词缀或临时效果后变化。
- `affixIds` 指向 `AffixDefinition`。
- 不允许直接修改 `TrigramDefinition`。

MVP 卦力建议：

```text
1 星 = 1
2 星 = 2
3 星 = 4
```

4 星留到后续扩展。

## 6. 64 卦配置

### 6.1 数据结构

`HexagramDatabase` 保存：

```text
hexagrams[]
```

每个 `HexagramDefinition`：

```text
id
displayName
outerTrigramId
innerTrigramId
specialEffectId
tags
descriptionTemplate
```

### 6.2 生成规则

默认效果由两部分组成：

```text
内卦行为 + 外卦修饰
```

生成步骤：

1. 根据 `innerTrigramId` 读取行为操作。
2. 根据 `outerTrigramId` 读取修饰操作。
3. 合并为默认效果序列。
4. 若存在 `specialEffectId`，只覆盖指定字段。
5. 生成显示文本和伤害明细。

特殊卦覆盖规则：

- 可以覆盖伤害倍率。
- 可以追加或替换效果操作。
- 可以修改目标和资源消耗。
- 未覆盖字段继续使用默认矩阵结果。

禁止用 `if (hexagramId == ...)` 散落在 `BattleCalculator` 中。

### 6.3 数据库验证

启动或编辑器验证时必须检查：

- 8×8 组合全部存在。
- 不存在重复 `id`。
- `outerTrigramId` 和 `innerTrigramId` 合法。
- 特殊效果引用的操作全部存在。
- 所有文本模板可生成。
- 没有缺失的五行或阴阳数据。

## 7. 效果操作

`EffectOperation` 是所有效果的最小执行单元：

```text
type
target
value
valueType
duration
conditionId
parameters
```

### 7.1 效果类型

MVP 支持：

```text
Damage
ApplyStatus
GainShield
DrawCard
GainEnergy
DiscardCard
ModifyDamage
ExtraTrigger
ChangeIntent
```

### 7.2 目标类型

```text
Self
Enemy
AllEnemies
RandomEnemy
SelectedCard
SourceCard
```

### 7.3 数值类型

```text
Flat
Percent
Multiplier
Stacks
Count
```

同一个效果操作只做一件事。复杂效果通过有序操作列表组合。

## 8. 武器配置

`WeaponDefinition` 建议字段：

```text
id
displayName
basePower
attackPattern
hitCount
elementAffinity
maxEnchantSlots
tags
description
```

`hitCount` 表示武器自身段数；实际段数由武器段数与内卦行为段数相乘。`attackPattern`：

```text
Single
MultiHit
AllTargets
Counter（预留，尚未接线）
```

MVP 武器：

- 玄铁重剑：单体、高基础
- 青锋剑诀：单体多段
- 暴雨梨花：群体多段

武器运行时状态另存：

```text
level
temporaryModifiers
enchantments[]
```

## 9. 法宝配置

`artifacts.csv` 当前字段：

```text
id
displayName
triggerType
conditionType
conditionValue
effects
description
```

已实现的触发类型：

```text
BeforeDamage
AfterPlay
```

已实现的条件类型：

```text
Always
FirstPlayEachTurn
InnerElement
Hexagram
```

规则：

- `BeforeDamage` 法宝在伤害计算前汇总修正；`Percent` 进入加法乘区，`Multiplier` 进入乘法乘区，加法先于乘法。
- `AfterPlay` 法宝在出卦即时效果和附魔写入后执行。
- `FirstPlayEachTurn` 以 `PlaysThisTurn == 0` 判断；玩家回合开始清零，成功出卦后递增。
- `InnerElement` 的 `conditionValue` 使用五行枚举值；`Hexagram` 使用卦象 ID。
- 法宝按 `battle_default.csv` 的 `defaultArtifactIds` 顺序加载，MVP 不做槽位随机。

## 10. 符箓配置

`talismans.csv` 当前字段：

```text
id
displayName
effects
description
```

规则：

- 符箓只允许在玩家 `PlayerAction` 阶段使用。
- 效果校验通过后才执行并消耗；失败不修改战斗状态。
- 抽牌类符箓在手牌已满或抽牌堆为空时视为不可生效，不消耗。
- 使用成功后发送 `TalismanUsed`，并同时从战斗内列表和本局 `RunState.TalismanIds` 移除。
- MVP 暂不支持目标选择；当前配置覆盖 `GainEnergy`、`GainShield` 和 `DrawCard`。
## 11. 敌人配置

`enemies.csv` 当前字段：

```text
id
displayName
kind
element
maxHp
basePower
intentMode
intentIds
ruleType
```

`enemy_intents.csv` 当前字段：

```text
id
type
power
status
statusStacks
statusDuration
weight
cooldown
conditionType
conditionValue
displayText
```

枚举：

```text
EnemyKind: Normal / Elite / Boss
EnemyIntentMode: Sequence / Weighted
EnemyIntentType: Attack / Defend / Debuff
EnemyIntentConditionType: Always / HpBelow / HpAbove / TurnAtLeast
EnemyRuleType: None / StatusImmune
```

规则：

- `intentIds` 使用分号分隔，并指向 `enemy_intents.csv` 的 ID。
- `Sequence` 按配置顺序循环；`Weighted` 按 `weight` 和战斗种子选择。
- `HpBelow`、`HpAbove` 的 `conditionValue` 是百分比；`TurnAtLeast` 是回合数。
- `cooldown` 表示同一意图两次入选之间至少间隔的回合数。
- `StatusImmune` 会使敌人拒绝所有 `AddStatus` 写入。
- 敌人意图必须在玩家回合开始前可见，且与实际执行内容一致。

## 12. 状态配置

`StatusDefinition` 建议字段：

```text
id
displayName
stackMode
maxStacks
decayTiming
triggerPoints
effects[]
description
```

MVP 状态：

| 状态 | 规则 |
|---|---|
| 灼烧 | 回合结束按层数受伤，层数 -1 |
| 易伤 | 受到伤害增加 |
| 虚弱 | 造成伤害降低 |
| 护盾 | 优先吸收伤害 |
| 破甲 | 忽略目标防御 |
| 寒滞 | 跳过或降低敌人行动 |

状态叠加和持续时间必须由同一份状态结算器处理。

## 13. 配置目录建议

```text
Assets/Resources/Config/Battle/
  trigrams.csv
  hexagrams.csv
  weapons.csv
  enemies.csv
  enemy_intents.csv
  artifacts.csv
  talismans.csv
  deck.csv
  battle_default.csv

Assets/Resources/Config/Run/
  run_nodes.csv
  run_realms.csv
  run_encounters.csv
  run_shop_offers.csv
  run_event_options.csv
```

同类配置数量较少时合并为 CSV 文件；新增配置类型时再增加独立 CSV，不要为了目录完整创建空文件。

`run_nodes.csv` 使用字段：`id`、`realmId`、`displayName`、`type`、`enemyId`、`rewardSpiritStones`。

`run_realms.csv` 使用字段：`id`、`displayName`、`promotionTargetRealmId`、`promotionRewardSpiritStones`。

`run_encounters.csv` 使用字段：`nodeId`、`encounterType`、`encounterId`。

`run_shop_offers.csv` 使用字段：`id`、`shopId`、`displayName`、`effectType`、`effectValue`、`price`、`description`。

`run_event_options.csv` 使用字段：`eventId`、`title`、`description`、`optionId`、`optionText`、`effectType`、`effectValue`、`resultText`。

## 14. 配置校验清单

新增内容后必须检查：

- ID 唯一且符合命名规范。
- 所有引用可解析。
- 文本不为空。
- 数值在允许范围内。
- 效果目标合法。
- 触发时机与效果类型匹配。
- 64 卦矩阵没有缺口。
- 编辑器验证和运行时加载使用同一套校验逻辑。
