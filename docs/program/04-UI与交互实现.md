# 04｜UI 与交互实现

> 版本：v0.1｜依赖：[02-战斗系统实现.md](02-战斗系统实现.md)、[03-数据配置规范.md](03-数据配置规范.md)

## 1. 目标

主战斗界面必须还原原型图的信息密度，同时保持实现简单：

- 玩家能快速看清手牌、灵力、附魔和敌人意图。
- 选内卦、选外卦、实时预览、出卦形成清晰闭环。
- 伤害数字和伤害明细一致。
- UI 不承担战斗规则计算。

## 2. 界面基准

| 项目 | 规格 |
|---|---|
| 设计分辨率 | 1920×1080 |
| 基准比例 | 16:9 |
| Canvas | Screen Space - Overlay |
| CanvasScaler | Scale With Screen Size |
| Match | 0.5 |
| 字体 | TextMeshPro，中文思源宋体或等价字体 |
| 输入 | 鼠标为主，手柄导航作为后续扩展 |

最小支持分辨率按 `1280×720` 验证，优先保证 16:9。

## 3. 原型区域拆分

主战斗界面分为六块：

```text
顶部状态栏
  ├─ 玩家信息
  ├─ 敌人信息
  └─ 关卡路线

中部卦台
  ├─ 内卦槽
  ├─ 外卦槽
  ├─ 卦象名称和效果
  └─ 伤害预览

右侧行动区
  ├─ 出卦
  ├─ 弃牌换牌
  ├─ 回合结束
  └─ 五行提示

中部下方法宝/符箓区
底部手牌区
```

## 4. UI 层级

```text
BattleHUD
  ├─ TopBar
  │   ├─ PlayerPanel
  │   ├─ EnemyPanel
  │   └─ RunRoutePanel
  ├─ CenterArea
  │   ├─ HexagramAltar
  │   ├─ HexagramPreview
  │   └─ DamagePreview
  ├─ ActionPanel
  ├─ ArtifactPanel
  ├─ TalismanPanel
  ├─ HandPanel
  ├─ TooltipLayer
  └─ AnimationLayer
```

`AnimationLayer` 必须独立于业务面板，用于伤害数字、飞行卡牌、状态图标和屏幕特效。

## 5. Prefab 规划

| Prefab | 用途 |
|---|---|
| `BattleCardView` | 手牌、牌堆预览、弃牌预览 |
| `EnemyView` | 敌人立绘、血条、状态和意图 |
| `ArtifactSlotView` | 法宝槽 |
| `TalismanSlotView` | 符箓槽 |
| `StatusChipView` | 状态图标和层数 |
| `DamageNumberView` | 伤害数字 |
| `HexagramPreviewView` | 卦名、组合、效果和伤害明细 |
| `TooltipView` | 卡牌、法宝、状态说明 |

手牌上限为 6，MVP 可以使用简单对象池；没有性能压力时不引入通用池化框架。

## 6. 交互流程

### 6.1 出卦

```text
点击一张手牌
  ↓
标记为内卦
  ↓
点击另一张手牌
  ↓
标记为外卦并显示卦象预览
  ↓
点击“出卦”
  ↓
锁定输入并播放结算
```

规则：

- 第一张始终是内卦。
- 第二张始终是外卦。
- 点击已选牌可以取消。
- 重新选择时立即重算预览。
- 只选一张时不允许出卦。
- 出卦后清除选择状态。

### 6.2 弃牌

- 点击“弃牌换牌”进入弃牌选择模式。
- 选择数量不得超过当前允许值。
- 确认后发指令，不直接改手牌。
- 取消后恢复普通出卦模式。

### 6.3 结束回合

- 点击“回合结束”后禁止继续出卦。
- 先播放玩家回合结束事件。
- 再播放敌人意图。
- 最后开始新的玩家回合。

## 7. 伤害预览

预览区至少展示：

```text
基础
× 卦象倍率
× 五行系数
× 法宝加算
× 法宝乘算
× 会心
= 最终伤害
```

显示要求：

- 最终伤害是视觉中心。
- 明细可以折叠或悬停查看。
- 能斩杀时显示明确的“可斩杀”状态。
- 五行克制和被克使用不同颜色。
- 预览值与实际伤害使用同一 `DamageBreakdown`。

MVP 不使用随机伤害，因此预览值必须等于实际结算值。

## 8. 状态与反馈

| 状态 | UI 反馈 |
|---|---|
| 可出卦 | 出卦按钮高亮 |
| 灵力不足 | 按钮变灰并显示原因 |
| 只选一张牌 | 提示“请选择外卦” |
| 同属性 | 显示 `×0.85` |
| 克制 | 显示 `×1.5` 和克制提示 |
| 被克 | 显示 `×0.67` 和受制提示 |
| 可斩杀 | 绿色标签 |
| 回合结算中 | 隐藏或禁用交互按钮 |
| 战斗结束 | 显示结算面板 |

错误提示不要弹系统对话框，优先使用界面内短提示。

## 9. BattleEvent 播放

`BattleView` 按队列播放事件：

```text
逻辑结算完成
  ↓
事件入队
  ↓
逐条播放
  ↓
播放结束
  ↓
恢复玩家输入
```

播放规则：

- 不允许 UI 在播放期间继续发指令。
- 伤害数字和状态变化使用事件携带的数值。
- 事件播放速度可配置。
- 提供“快速播放”或点击跳过动画的后续扩展位，MVP 可以先不实现。

## 10. 布局与适配

- 顶部和底部面板使用固定高度。
- 中部卦台使用弹性布局。
- 手牌数量变化时只调整卡牌间距，不缩放卡牌文字。
- 文本使用 TMP 自动换行，关键数值不允许被裁切。
- 所有面板使用锚点适配，避免依赖绝对坐标。
- 工具提示层级必须高于所有普通面板。

## 11. 输入与手柄

键鼠 MVP 必须支持：

- 鼠标点击
- 鼠标悬停查看详情
- 键盘确认/取消作为可选增强

如果引入 Input System：

- 使用 `InputSystemUIInputModule`。
- 鼠标和手柄最终都生成 `BattleCommand`。
- UI 只负责将输入转换为指令，不直接调用战斗状态。
- 手柄导航顺序需要单独设计，不能依赖 Unity 默认自动顺序。

## 12. 视觉实现边界

- 主界面以 uGUI 实现。
- 背景、粒子、命中特效可以使用 URP 2D 或 UI 粒子。
- MVP 不依赖复杂 Shader 完成核心反馈。
- 伤害数字、状态层数和资源变化必须优先保证可读性。
- 大数字可以使用缩放和分段动画，但不得改变实际数值。

## 13. 验收标准

- 1920×1080 下与原型图信息结构一致。
- 1280×720 下无关键文字裁切和按钮重叠。
- 内外卦选择顺序清晰。
- 预览伤害与实际伤害一致。
- 出卦、弃牌、结束回合状态切换正确。
- 战斗结束后面板不可继续操作。
- 快速连续点击不会重复出牌或重复结算。
