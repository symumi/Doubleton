# 04｜UI 与交互实现

> 版本：v0.2｜更新：2026-09-10｜依赖：[02-战斗系统实现.md](02-战斗系统实现.md)、[03-数据配置规范.md](03-数据配置规范.md)

## 1. 目标

主战斗界面必须还原原型图的信息密度，同时保持实现简单：

- 玩家能快速看清手牌、灵力、附魔和敌人意图。
- 选内卦、选外卦、实时预览、出卦形成清晰闭环。
- 伤害数字和伤害明细一致。
- UI 不承担战斗规则计算。

## 2. 界面基准

| 项目 | 规格 |
|---|---|
| 设计分辨率 | 1920×1080 |
| 基准比例 | 16:9 |
| Canvas | Screen Space - Overlay |
| CanvasScaler | Scale With Screen Size |
| Match | 0.5 |
| 字体 | TextMeshPro，中文思源宋体或等价字体 |
| 输入 | 鼠标为主，手柄导航作为后续扩展 |

最小支持分辨率按 `1280×720` 验证，优先保证 16:9。

## 3. 原型区域拆分

主战斗界面分为六块：

```text
顶部状态栏
  ├─ 玩家信息
  ├─ 敌人信息
  └─ 关卡路线

中部卦台
  ├─ 内卦槽
  ├─ 外卦槽
  ├─ 卦象名称和效果
  └─ 伤害预览

右侧行动区
  ├─ 出卦
  ├─ 弃牌换牌
  ├─ 回合结束
  └─ 五行提示

中部下方法宝/符箓区
底部手牌区
```

## 6. 交互流程

### 6.1 出卦

```text
点击一张手牌
  ↓
标记为内卦
  ↓
点击另一张手牌
  ↓
标记为外卦并显示卦象预览
  ↓
点击“出卦”
  ↓
锁定输入并播放结算
```

规则：

- 第一张始终是内卦。
- 第二张始终是外卦。
- 点击已选牌可以取消。
- 重新选择时立即重算预览。
- 只选一张时不允许出卦。
- 出卦后清除选择状态。

### 6.2 弃牌

- 点击“弃牌换牌”进入弃牌选择模式。
- 选择数量不得超过当前允许值。
- 确认后发指令，不直接改手牌。
- 取消后恢复普通出卦模式。

### 6.3 结束回合

- 点击“回合结束”后禁止继续出卦。
- 先播放玩家回合结束事件。
- 再播放敌人意图。
- 最后开始新的玩家回合。

## 7. 伤害预览

预览区至少展示：

```text
基础
× 卦象倍率
× 五行系数
× 法宝加算
× 法宝乘算
× 会心
= 最终伤害
```

显示要求：

- 最终伤害是视觉中心。
- 明细可以折叠或悬停查看。
- 能斩杀时显示明确的“可斩杀”状态。
- 五行克制和被克使用不同颜色。
- 预览值与实际伤害使用同一 `DamageBreakdown`。

MVP 不使用随机伤害，因此预览值必须等于实际结算值。

## 8. 状态与反馈

| 状态 | UI 反馈 |
|---|---|
| 可出卦 | 出卦按钮高亮 |
| 灵力不足 | 按钮变灰并显示原因 |
| 只选一张牌 | 提示“请选择外卦” |
| 同属性 | 显示 `×0.85` |
| 克制 | 显示 `×1.5` 和克制提示 |
| 被克 | 显示 `×0.67` 和受制提示 |
| 可斩杀 | 绿色标签 |
| 回合结算中 | 隐藏或禁用交互按钮 |
| 战斗结束 | 显示结算面板 |

错误提示不要弹系统对话框，优先使用界面内短提示。

当前原型已通过 UGUI `BattleFeedbackView` 接入：可斩杀提示、出卦/符箓/回合结算浮层、上升/缩放/抖动/淡出动画和反馈播放期间输入锁。动画参数位于 `Assets/Resources/Config/UI/battle_feedback_animation.csv`；逐事件动画队列、屏幕震动、粒子和可跳过动画仍待接入。

## 9. BattleEvent 播放

`BattleView` 按队列播放事件：

```text
逻辑结算完成
  ↓
事件入队
  ↓
逐条播放
  ↓
播放结束
  ↓
恢复玩家输入
```

播放规则：

- 不允许 UI 在播放期间继续发指令。
- 伤害数字和状态变化使用事件携带的数值。
- 事件播放速度可配置。
- 提供“快速播放”或点击跳过动画的后续扩展位，MVP 可以先不实现。

## 10. 布局与适配

- 顶部和底部面板使用固定高度。
- 中部卦台使用弹性布局。
- 手牌数量变化时只调整卡牌间距，不缩放卡牌文字。
- 文本使用 TMP 自动换行，关键数值不允许被裁切。
- 所有面板使用锚点适配，避免依赖绝对坐标。
- 工具提示层级必须高于所有普通面板。

## 11. 输入与手柄

键鼠 MVP 必须支持：

- 鼠标点击
- 鼠标悬停查看详情
- 键盘确认/取消作为可选增强

如果引入 Input System：

- 使用 `InputSystemUIInputModule`。
- 鼠标和手柄最终都生成 `BattleCommand`。
- UI 只负责将输入转换为指令，不直接调用战斗状态。
- 手柄导航顺序需要单独设计，不能依赖 Unity 默认自动顺序。

## 12. 视觉实现边界

- 主界面以 uGUI 实现。
- 背景、粒子、命中特效可以使用 URP 2D 或 UI 粒子。
- MVP 不依赖复杂 Shader 完成核心反馈。
- 伤害数字、状态层数和资源变化必须优先保证可读性。
- 大数字可以使用缩放和分段动画，但不得改变实际数值。

## 13. 验收标准

- 1920×1080 下与原型图信息结构一致。
- 1280×720 下无关键文字裁切和按钮重叠。
- 内外卦选择顺序清晰。
- 预览伤害与实际伤害一致。
- 出卦、弃牌、结束回合状态切换正确。
- 战斗结束后面板不可继续操作。
- 快速连续点击不会重复出牌或重复结算。

## 14. UI 页面与组件清单

> 本节用于统一规划正式 UI 的页面边界、弹窗层级和战斗 HUD 组件，作为后续 Prefab 拆分和 View 实现的基线。

### 14.1 分类原则

UI 分为四类，避免把详情、提示和临时操作都做成独立页面：

| 分类 | 说明 | 实现方式 |
|---|---|---|
| 一级页面 | 承载完整的流程节点或主要功能 | 每个页面一个 Prefab，由页面控制器切换 |
| 弹窗与浮层 | 确认、详情、奖励、错误和临时操作 | 统一挂在 `PopupLayer` 或 `OverlayLayer` |
| 战斗 HUD 组件 | 战斗内持续展示的资源、状态和操作 | 组件 Prefab，由 `BattleHudView` 组合 |
| 表现层 | 动画、伤害数字、提示和工具提示 | 独立 Layer，不承载业务状态 |

页面只负责展示和转发指令，不直接修改战斗或局内状态。

### 14.2 一级页面

| 页面 | 作用 | 当前状态 | 优先级 |
|---|---|---|---|
| `Boot/LoadingView` | 加载 CSV、存档和运行环境，提供加载反馈 | 当前无独立界面，由运行时自动初始化 | P0 |

| `RunMapView` | 显示路线、节点状态、当前境界、灵石和天劫 | 当前运行时原型已有 | P0 |
| `WeaponSelectView` | 新局选择初始武器、查看武器特性 | 当前集成在路线页按钮中，建议独立页面或弹窗 | P0 |
| `BattleHudView` | 战斗主界面和玩家操作 | 当前运行时原型已有 | P0 |
| `BattleResultView` | 胜利/失败结果、奖励和确认继续 | 当前运行时原型已有 | P0 |
| `ShopView` | 商品列表、刷新、购买和离开 | 当前运行时原型已有 | P0 |
| `EventView` | 奇遇描述、选项、结果和离开 | 当前运行时原型已有 | P0 |
| `RealmPromotionView` | 渡劫胜利后的境界晋升 | 当前运行时原型已有 | P0 |
| `RunResultView` | 本局胜利/失败结算和道行奖励 | 当前运行时原型已有 | P0 |
| `MetaProgressView` | 道行、天劫选择、局外进度和解锁状态 | 当前运行时原型已有 | P1 |
| `CodexView` | 64 卦列表、详情和熟练度 | 当前运行时原型已有 | P1 |
| `SettingsView` | 音量、分辨率、语言、键位和返回主菜单 | 尚未实现 | P1 |
| `PauseView` | 战斗中暂停、设置和返回主菜单 | 尚未实现 | P1 |
| `SaveSlotView` | 多存档槽、覆盖确认和删除存档 | 后续版本 | P2 |
| `AchievementView` | 成就、统计和历史记录 | 后续版本 | P2 |

推荐主流程：

```text
Boot
  ↓
MainMenu
  ├─ 继续游戏 → 恢复存档 → RunMap
  └─ 开始修行 → WeaponSelect → RunMap
                         ↓
                       Battle
                         ↓
                   BattleResult
                    ├─ 胜利 → Shop / Event → RunMap
                    ├─ 渡劫 → RealmPromotion → RunMap
                    └─ 失败 → RunResult
                         ↓
                   MetaProgress → MainMenu
```

### 14.3 弹窗与浮层

| 界面/组件 | 用途 | 优先级 |
|---|---|---|
| `ConfirmPopup` | 确认放弃进度、覆盖存档、退出游戏 | P0 |
| `ToastView` | 灵石不足、法宝栏已满、操作失败等短提示 | P0 |
| `TooltipView` | 卡牌、卦象、状态、法宝和武器说明 | P0 |
| `CardDetailPopup` | 手牌完整信息、牌面效果和来源 | P1 |
| `HexagramDetailPopup` | 卦象效果、倍率、五行和熟练度 | P1 |
| `DamageBreakdownPopup` | 基础、卦象、五行、法宝、会心、防御明细 | P1 |
| `StatusDetailPopup` | 状态层数、持续回合和触发时机 | P1 |
| `RewardSelectPopup` | 三选一奖励、牌组奖励和祝福选择 | P1 |
| `ShopPurchaseConfirmPopup` | 购买确认、价格和拥有上限提示 | P1 |
| `DeckViewerPopup` | 查看当前牌组、排序和删牌模式 | P1 |
| `SettingsPopup` | 战斗中或主菜单设置 | P1 |
| `SaveRecoveryPopup` | 主存档损坏时使用备份恢复 | P1 |
| `TutorialPromptPopup` | 首次进入战斗、首次打开坊市等引导 | P2 |

弹窗必须由统一的 `PopupService` 或等价页面栈管理，禁止每个页面自行创建互不兼容的遮罩和关闭逻辑。

### 14.4 战斗 HUD 组件

#### 顶部信息区

- `PlayerStatusView`：生命、护盾、灵力、状态
- `EnemyView`：敌人名称、生命、护盾、五行和状态
- `EnemyIntentView`：敌人当前意图和预计伤害
- `RunRouteStripView`：当前境界、节点进度和天劫等级

#### 中部卦台区

- `HexagramAltarView`：内卦槽和外卦槽
- `HexagramPreviewView`：卦象名称、组合和效果说明
- `DamagePreviewView`：预计伤害、可斩杀提示和五行克制提示
- `DamageBreakdownView`：伤害明细
- `HexagramAnimationView`：出卦组合动画和目标反馈

#### 资源区

- `ArtifactPanelView`：法宝槽和触发提示
- `TalismanPanelView`：符箓按钮和使用反馈
- `StatusBarView`：状态图标、层数和剩余回合
- `EnergyView`：灵力变化动画

#### 手牌与行动区

- `HandPanelView`：手牌布局和数量变化
- `BattleCardView`：单张卡牌展示、选中、内卦/外卦标记
- `ActionPanelView`：出卦、弃牌和结束回合
- `DiscardSelectView`：弃牌选择模式、确认和取消
- `BattleLogView`：战斗日志和最近事件

#### 表现层

- `BattleFeedbackLayer`：出卦、符箓和回合结算提示
- `DamageNumberLayer`：伤害数字、护盾吸收和状态变化
- `AnimationLayer`：飞行卡牌、命中、屏幕震动和粒子
- `TooltipLayer`：悬停详情
- `InputBlockLayer`：动画播放期间拦截输入

### 14.5 最小 MVP 范围

最小可玩闭环至少需要：

```text
MainMenu
WeaponSelect
RunMap
BattleHud
BattleResult
Shop
Event
RealmPromotion
RunResult
MetaProgress
Codex
```

再补三个基础公共组件：

```text
ConfirmPopup
ToastView
TooltipView
```

这样可以覆盖“新局 → 路线 → 战斗 → 奖励 → 坊市/奇遇 → 晋升 → 结算 → 局外成长”的完整流程。

### 14.6 推荐层级与 Prefab 命名

```text
UIRoot
  ├─ BackgroundLayer
  ├─ PageLayer
  │   ├─ MainMenuView
  │   ├─ RunMapView
  │   ├─ BattleHudView
  │   ├─ ShopView
  │   └─ ...
  ├─ PopupLayer
  ├─ TooltipLayer
  ├─ ToastLayer
  └─ AnimationLayer
```

建议优先将一级页面 Prefab 化，再将战斗 HUD 拆成子组件。当前 `BattlePrototypeBootstrap` 只保留流程编排和临时入口；正式实现逐步迁移到 `MainMenuView`、`RunMapView`、`BattleHudView` 等独立 View。

### 14.7 实施顺序

1. 完成 `UIRoot`、页面栈、弹窗栈和输入锁。
2. Prefab 化 `MainMenuView`、`RunMapView`、`BattleResultView`、`RunResultView` 和 `MetaProgressView`。
3. 拆出 `BattleHudView` 及顶部信息、手牌、卦台、行动、资源和表现层组件。
4. 接入 `ConfirmPopup`、`ToastView`、`TooltipView` 和详情弹窗。
5. 接入设置、暂停、存档槽、成就和教程。
6. 最终移除原型专用的运行时 UI 构建代码。
