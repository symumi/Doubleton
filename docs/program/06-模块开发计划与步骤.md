## 1. 当前基线

当前工程已经完成 M1 战斗垂直切片：

- 8 卦、64 卦组合、五行、伤害预览与实际结算同源。
- 手牌、抽牌堆、弃牌堆、灵力、敌人回合和胜负判定。
- 八卦、卦象、武器、敌人、牌组和战斗默认值已 CSV 化。
- 运行时原型 UI 可以完成一场战斗。
- Roslyn 编译通过，EditMode 战斗测试通过。

M2 单局闭环已完成，M3-1 武器与攻击模式、M3-2 附魔槽、M3-3 法宝与符箓、M3-4 敌人意图池已落地；M4-0 存档与继续游戏已完成，支持局外/局内/战斗快照自动存档、主界面继续游戏和损坏备份回退。下一阶段进入 M4-1 64 卦特殊效果与图鉴。

## 2. 实施原则

- 按模块文档的依赖顺序推进：先流程状态和数据，再 UI，再内容。
- 每个工作包必须形成可测试闭环，不一次性铺满内容。
- 规则计算留在纯 C# 核心，UI 只发命令和展示事件。
- 新增静态内容继续使用 CSV；新增 ID 和字段遵循 `12-数据字典与命名规范.md`。
- 未实现的系统只保留明确入口和 `TODO`，不写假实现。

## 5. 已完成开发批次

### 5.1 M2-1 单局进度核心（已完成）

#### 步骤

1. 新增 `Assets/Resources/Config/Run/run_nodes.csv`，记录 3 境界 × 3 关。
2. 新增 `RunNodeDefinition`、`RunConfigDatabase`、`CsvRunConfigLoader`、`ResourcesRunConfigLoader`。
3. 新增 `RunState`、`RunController`，实现顺序推进、灵石奖励、渡劫晋升、失败结束。
4. 扩展 `BattleController.CreatePrototype`，允许按关卡传入敌人 ID。
5. 将原型启动入口改为“创建本局 → 进入当前关战斗”。
6. 增加 `RunCoreTests`，覆盖节点数量、顺序推进、奖励、渡劫和失败。

#### 验收

- `run_nodes.csv` 有 9 个战斗节点。
- 初始节点为 `node_01`，状态为 `Map`。
- 普通/精英胜利后当前节点前进，并获得配置灵石。
- 渡劫胜利后先进入 `RealmPromotion`，调用晋升后才前进。
- 最终渡劫完成后本局结果为 `Victory`。
- 任意战斗失败后本局结果为 `Defeat`，状态为 `RunResult`。
- 原型 UI 可以通过“继续”按钮连续推进关卡。

### 5.2 M2-2 路线页与战斗入口（已完成）

#### 步骤

1. 在 `BattlePrototypeBootstrap` 中增加 `RUN_MAP` 原型页，以 3×3 网格展示 9 个节点。
2. 按 `CurrentNodeIndex` 显示已通关、当前和未解锁状态。
3. 展示当前节点境界、类型、敌人和灵石奖励。
4. 将启动流程改为“创建本局 → 路线页 → 开始战斗 → 战斗 → 返回路线页”。
5. 胜利后只推进节点并回到路线页，不自动进入下一场战斗。
6. 失败或最终通关后显示本局结算状态，并保留重新开始入口。

#### 验收

- 初始进入路线页，不会自动开战。
- 当前节点高亮，已通关节点显示完成标记，未解锁节点灰置。
- 点击“开始战斗”进入当前节点，不能跳关。
- 战斗结束点击“继续”后回到路线页。
- 普通/精英胜利后解锁下一节点；渡劫胜利后完成晋升并回到路线页。
- 失败和最终通关显示对应结算文本。

### 5.3 M2-3 战斗结果与奖励写回（已完成）

#### 步骤

1. 新增 `RunPhase.BattleResult`，战斗结束后先进入独立结算阶段。
2. `RunState` 保存待确认的战斗结果与灵石奖励。
3. `CompleteBattle` 只记录结果，不直接发奖或推进节点。
4. 新增 `ConfirmBattleResult`，确认后统一发放奖励、记录已通关节点并推进流程。
5. 原型增加 `BATTLE_RESULT` 页面，显示胜利/失败、节点和灵石奖励。
6. 增加重复确认测试，防止快速点击导致奖励重复发放。

#### 验收

- 战斗结束后进入 `BattleResult`，灵石和节点进度尚未变化。
- 胜利确认后只发放一次配置灵石，并解锁下一关。
- 失败确认后进入 `RunResult`。
- 重复调用 `ConfirmBattleResult` 返回失败，不重复奖励。
- 渡劫胜利确认奖励后继续原有晋升流程。

### 5.4 M2-4 坊市与奇遇（已完成）

#### 步骤

1. 新增 `RunPhase.Shop`、`RunPhase.Event` 和 `RunEncounterType`，将遭遇触发点从节点配置中拆到独立 `run_encounters.csv`。
2. 新增坊市商品与奇遇选项配置，运行时通过 `RunEncounterDatabase` 查询。
3. `RunState` 保存本局牌组、最大生命/武器力道加成、坊市刷新与购买状态、奇遇结算状态。
4. 实现购买、刷新、离开坊市，以及奇遇选项结算和离开事件；效果写回本局状态并影响下一场战斗。
5. 原型新增 `SHOP`、`EVENT` 页面，展示商品、价格、购买状态和奇遇选项/结果。
6. 增加购买持久化与事件奖励测试。

#### 验收

- 渡劫晋升后按配置进入坊市，普通/精英节点可触发奇遇。
- 坊市可购买商品、刷新货架和离开；重复购买、灵石不足和无效商品返回失败。
- 奇遇选项只结算一次，结算后离开回到路线页。
- 最大生命、武器力道、删牌和灵石效果写入本局状态，并在下一场战斗生效。
- 当前限制：商品池为固定配置轮换，无随机权重；无法宝/符箓池；删牌固定删除牌组第一张，后续需接 UI 选牌。

### 5.5 M2-5 渡劫晋升与一局结算（已完成）

#### 步骤

1. 新增 `run_realms.csv`，记录境界显示名、晋升目标和晋升灵石奖励。
2. 渡劫胜利确认战斗奖励后进入独立 `REALM_PROMOTION` 页面，不再自动跳过晋升。
3. 晋升确认时发放境界奖励，再进入下一境界或本局结算。
4. 失败或最终渡劫通关后进入 `RUN_RESULT`，按结果计算道行奖励。
5. 确认本局结算后进入 `META_PROGRESS` 原型页，展示累计道行、完成局数和最高天劫。
6. 增加晋升奖励只发一次、失败道行结算和通关天劫解锁测试。

#### 验收

- 渡劫胜利后先显示晋升页面，确认后奖励只发放一次。
- 炼气/筑基晋升分别发放配置中的灵石奖励；元婴渡劫后进入本局通关结算。
- 失败结算获得少量道行，通关结算获得较高道行并解锁天劫 1。
- `RUN_RESULT` 确认后进入 `META_PROGRESS`，重新开始不会丢失当前进程内的道行。
- 当前限制：道行解锁商店、图鉴熟练度、天劫词条和符箓/法宝晋升奖励尚未接入；永久进度已由 M4-0 存档承接。

### 5.6 M3-1 武器与攻击模式（已完成）

#### 步骤

1. 扩展 `weapons.csv`，新增 `attackPattern` 和 `hitCount` 字段，并配置玄铁重剑、青锋剑诀、暴雨梨花三把武器。
2. 新增 `AttackPattern.Single / MultiHit / AllTargets`，由武器配置决定攻击模式。
3. `BattleCalculator` 计算实际段数：武器段数 × 内卦行为段数；伤害按段数逐段结算。
4. 武器五行亲和与内卦五行一致时，基础伤害获得 `×1.25` 加成，并写入 `DamageBreakdown` 预览公式。
5. `BattleController` 支持按武器 ID 创建战斗；本局默认武器 ID 通过 `RunState` 传入。
6. 原型路线页在首战前提供武器切换入口，开战后锁定武器。
7. 原型预览显示攻击模式、每段伤害和连击段数。

#### 验收

- 三把武器具有可区分的攻击模式、基础力道和五行亲和，并可在首战前切换。
- 多段武器会按配置段数实际扣除敌人 HP，而不是只显示段数。
- 五行亲和加成只在内卦五行与武器亲和一致时生效。
- 群攻模式保留 `AllTargets` 配置和计算标记；当前原型只有单个敌人，多目标结算待接入。
- 当前限制：反击模式、多敌人目标和每段独立会心尚未实现。

### 5.7 M3-2 附魔槽（已完成）

#### 步骤

1. `EnchantInstance` 保存来源卦、对应 `EffectOperation`、写入顺序和剩余回合。
2. `WeaponState.AddEnchant` 只接收 `Duration > 0` 的持续效果，槽满时移除最旧附魔，并用单调递增顺序保留 FIFO 语义。
3. `BattleResolver.ResolvePlay` 在即时效果结算后，将本手卦象的持续效果写入玩家武器附魔槽。
4. `WeaponState.TickTurn` 在玩家回合开始递减剩余回合并移除过期附魔；附魔不跨战斗保留。
5. 原型预览区展示当前 3 个附魔槽及剩余回合，槽满且本手会写入附魔时提示将顶替最旧附魔。
6. 增加第 4 个附魔顶替、持续回合过期和结算写入附魔槽的 EditMode 测试。

#### 验收

- 带持续时间的卦象效果会在出卦结算后写入附魔槽。
- 第 4 个附魔正确顶替第 1 个，槽内顺序保持先入先出。
- 附魔在玩家回合开始递减，持续回合归零后移除。
- 原型战斗界面显示附魔槽、效果名、来源卦和剩余回合。
- 当前限制：已配置的短持续效果仍由 `StatusInstance` 负责实际数值结算，附魔槽负责 FIFO、计时和 UI，不重复触发本手效果；法宝与符箓由 M3-3 独立结算。

### 5.8 M3-3 法宝与符箓（已完成）

#### 步骤

1. 新增 `ArtifactDefinition`、`TalismanDefinition` 和对应 CSV，法宝使用 `triggerType/conditionType/conditionValue/effects` 配置触发条件与效果，符箓使用 `effects` 配置一次性效果。
2. `ArtifactRules` 汇总 `BeforeDamage` 法宝，支持 `Always`、`FirstPlayEachTurn`、`InnerElement`、`Hexagram` 条件；伤害修正先合并加法乘区，再合并乘法乘区。
3. `BattleCalculator` 接入法宝伤害乘区；`BattleResolver.ResolvePlay` 在出卦即时效果和附魔写入后触发 `AfterPlay` 法宝，并维护每回合出卦次数。
4. `BattleResolver.ResolveTalisman` 执行符箓效果并发送 `TalismanUsed`；`BattleController.UseTalisman` 只在玩家行动阶段执行，成功后从战斗内符箓列表移除。
5. `RunState` 保存本局法宝和符箓列表，`RunController` 初始化默认配置、传入战斗并在符箓成功使用后同步移除。
6. 原型战斗界面显示当前法宝和符箓按钮；非玩家行动阶段禁用符箓，抽牌类符箓在手牌已满或抽牌堆为空时不消耗。
7. 增加法宝加算/乘算、每回合首手、出卦后触发、符箓使用消耗和局内列表同步测试。

#### 验收

- 法宝伤害先加算后乘算，预览与执行使用同一计算路径。
- 每回合首手法宝只触发一次，火属性内卦和指定卦象条件可正确匹配。
- `AfterPlay` 法宝在出卦结算后触发效果并产生 `ArtifactTriggered` 事件。
- 符箓只在玩家行动阶段可用；无法生效时不消耗，成功后同时从战斗和本局列表移除。
- 原型界面显示法宝列表与符箓按钮，非玩家行动阶段不可操作。
- 当前限制：MVP 只接入 `BeforeDamage`、`AfterPlay` 两类法宝触发和 3 个示例符箓；符箓暂不支持目标选择，出卦后及符箓触发的抽牌暂不重洗弃牌堆。

### 5.9 M3-4 敌人意图池（已完成）

#### 步骤

1. 扩展 `enemies.csv`，增加敌人类型、意图模式、意图 ID 列表和规则类型；新增 `enemy_intents.csv` 配置攻击、防御、减益等意图。
2. 新增 `EnemyIntentDefinition`、`EnemyKind`、`EnemyIntentMode`、`EnemyIntentConditionType` 和 `EnemyRuleType`，运行时意图携带配置 ID。
3. 新增 `EnemyIntentSelector`，按 `Sequence` 顺序循环或按 `Weighted` 权重选择；支持 `Always`、`HpBelow`、`HpAbove`、`TurnAtLeast` 条件和冷却回合。
4. `BattleController.SelectEnemyIntent` 改为读取 `EnemyDefinition.Intents`，意图在玩家回合开始前生成并通过 `EnemyIntentChanged` 提供给 UI。
5. 实现 `StatusImmune` Boss 规则：敌人免疫状态时 `AddStatus` 返回失败，结算层发送“敌方免疫状态”事件。
6. 增加意图池加载、条件跳过、权重确定性、状态免疫和敌人行动一致性测试。

#### 验收

- `enemies.csv` 中的意图 ID 能正确解析为运行时意图池。
- 顺序模式按配置循环，条件不满足的意图会跳过。
- 权重模式使用战斗种子，重复运行结果一致。
- 敌人当前意图的显示文本、数值和实际执行结果一致。
- `StatusImmune` 敌人不会获得控制/减益状态。
- 当前限制：MVP 意图类型只实现攻击、防御、减益，尚未实现召唤、改变环境和蓄力；Boss 规则只实现 `StatusImmune`，九关仍共用占位敌人。

### 5.10 M4-0 存档与继续游戏（已完成）

#### 步骤

1. 新增 `Assets/Scripts/Save/`，使用 `GameSaveData` 分层保存局外、局内和战斗快照；存档包含 `save_version`、更新时间、牌堆顺序、敌人意图、附魔槽和商店/奇遇状态。
2. 新增 `SaveFileStorage`，写入采用临时文件加原子替换，并保留 `.bak` 备份；主存档损坏或版本不兼容时尝试读取备份。
3. 新增 `SaveService`，负责状态捕获、JSON 序列化、版本校验、数值裁剪、未知内容忽略和控制器恢复；战斗恢复直接构建 `PlayerState`/`EnemyState`/`BattleState`，不调用 `StartPlayerTurn`。
4. 原型启动改为主菜单：有局内存档时显示“继续游戏”，开始新游戏需二次确认；进入新局、战斗初始化、玩家回合开始、战斗结算、坊市购买/刷新、奇遇结算、境界晋升和一局结束时自动存档。
5. 新增 `SaveCoreTests`，覆盖局内外状态往返、战斗回合边界、手牌/抽牌堆顺序、坊市状态、文件往返和损坏主存档回退。

#### 验收

- 有有效局内存档时主菜单显示“继续游戏”，无存档时只显示开始修行。
- 战斗内退出后继续，回到保存时的玩家回合开始状态；手牌、抽牌堆、灵力、敌人当前意图、附魔和状态不重掷。
- 恢复战斗不会重复执行回合开始回灵、抽牌或附魔计时。
- 坊市刷新次数、商品列表、购买状态和奇遇结果按存档恢复。
- 主存档损坏时能读取上一份备份；局外道行、天劫等级和完成局数可跨启动保留。
- 当前限制：战斗事件日志不进入存档，恢复后日志为空；战斗随机数内部状态未序列化，后续回合的随机抽牌/权重意图可能使用新的随机序列；跨战斗玩家气血尚未写回 `RunState`，等待后续规则确认；手动多槽位和云存档不在本批范围。
